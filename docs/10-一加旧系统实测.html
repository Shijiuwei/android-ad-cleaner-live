10 一加旧系统实测：Ace 2 Pro / ColorOS 14

实测日期：2026-10-25。设备为一加 Ace 2 Pro（PJA110），系统 PJA110_14.0.0.812(CN01)、Android 14，屏幕 1240 × 2772。通过 Mac 上的 adb 执行；这不是 Windows 连接该手机的测试，也不能代替小米 OS4.0.27 的复测。

最初商店显示「无网络连接」，手机日期为 2026-02-05，电脑日期为 2026-10-25。机主联网后，手机日期也变为 2026-10-25；脚本没有修改网络或时间。联网后服务管理列表增加了项目，部分目标移到下一屏，因此补入跨页查找、目标回读和其他开关保留检查。

应用版本与适配范围

系统版本和应用版本会分别影响入口。本次实际安装的版本如下：

应用版本本次结果
下拉搜索11.31.4「设置 → 账号与隐私 → 隐私 → 个性化推荐」已找到并关闭
软件商店12.21.0「我的 → 设置 → 隐私 → 个性化推荐」是二级设置页；个性化推荐已关闭
软件商店推广位同上机主联网后，六项明确推广位已关闭并跨页回读；其他服务开关保持原样
浏览器40.10.1.9「我的 → 设置 → 隐私 → 个性化推荐」已找到并关闭；参考脚本的「主页设置 / 广告管理」入口未匹配
主题商店11.6.3修复首屏少量文字被误判为空白广告后，可正常停留在本应用首页；广告设置入口仍待适配
视频40.7.11.1「我的」页设置使用无文字图标，未完成广告开关验证

系统广告入口实际为「设置 → 权限与隐私 → 隐私 → 设备标识与广告 → 广告跟踪」。该页使用逐应用状态列表，而不是参考脚本预期的一页开关；本次没有自动处理这张列表。系统设置里也未匹配到参考脚本的「OPPO AI → 小布建议」。

原参考脚本与专用脚本

先备份，再以安全模式完整执行 ColorOS 16 的同品牌参考脚本，用时 324 秒，仅调整下拉搜索个性化推荐 1 项。其余项目存在入口不匹配或保护性停止，不能将命令退出码 0 当作全部成功。

随后按实机页面补入 recipes/oneplus-PJA110/recipe.py，包含下拉搜索、软件商店、商店推广位、浏览器四段。只处理明确列出的开关，操作前确认目标，操作后回读。入口缺失或开关仍开时记录未完成步骤，CLI 返回非零；已成功改动的日志仍保留。

修复冷启动等待后，最终在四个可选组件保持挂起时完整复跑四段：155 秒，9 项回读为关闭、调整 0 项、未完成步骤 0 个，退出码 0。

商店推广位仅选以下六项：悬浮活动图标、活动弹窗、顶部轮播卡片、底部活动专区、游戏详情页活动卡片、软件福利。下载更新、应用安全、普通游戏分类、快应用入口不在该名单中。联网后的关闭段用时 96 秒，6 项全部回读关闭，未完成步骤为 0；同时核对列表中其他开关与操作前一致。

营销通知

初次扫描找到 27 个候选，保留混合付款渠道、两项直播提醒和用途不明确的「重要资讯」，选择 23 个明确的营销渠道。

旧版引擎跳过了 ColorOS 14 独立的通知设置应用。修复后仅接受实测的两个 Activity：

  • com.oplus.notificationmanager.ChannelNotificationSettingsActivity
  • com.oplus.notificationmanager.AppNotificationSettingsActivity（仅用于找到渠道入口，不允许把应用总开关当作渠道开关）

仍须核对渠道标题及明确的「允许通知」开关。23 个渠道关闭后，回读仍开启数量为 0。首次关闭完成时，对照 368 个既有渠道，其余渠道状态和各应用通知总开关均与备份一致，当时新增 2 个渠道。

联网并完成全部复跑后：23 个目标仍关闭，所有应用通知总开关仍与备份一致；新增渠道共 13 个。另有 1 个非目标渠道发生变化：天气的「天气提醒」重要级别由 4 变为 3，mUserLockedFields 由 0 变为 34，仍处于开启状态。它不在本次关闭清单中，变化原因尚未确认；公开记录保留这项差异，不能把最后结果写成「所有非目标状态都未变」。

Google Play 的「付款事宜、特惠信息和推荐内容」同时承载付款通知，已补入扫描排除规则；不能仅因名称带「推荐」就关闭它。

引擎修复与验证边界

  • 首屏有一两个标签也可能是正常页面，不能当作空白广告按返回。
  • 商店冷启动曾出现短暂空白，旧逻辑在 3 秒后按返回会退出正常应用。现在最多等待 8 秒，只处理可识别的关闭 / 拒绝按钮；仍无页面就报失败，不盲按返回。读取及弹窗处理前后均核对前台包。
  • 慢启动完成后仍给更新、引导弹窗留出处理时间。
  • 商店会弹出系统通知权限申请，遮住应用首页；仅点明确的「拒绝 / 不允许」，没有拒绝按钮则停止。权限弹窗在首页出现后才弹出时也处理，不自动授予权限。该商店通知总开关在操作前已经关闭，操作后保持关闭。
  • 商店沿用引擎的「停止目标 App，再从桌面入口启动」，浏览器使用已验证的公开 Activity 并清理旧任务，避免退出或复用上次设置子页。商店在四个可选组件挂起后仍可正常进入首页；没有清除应用数据。
  • 专用脚本以实际 Activity 确认设置页是否打开，处理第一次点击被切换动画吞掉的情况。
  • 联网后商店服务列表变长，必须先跨页找到全部指定目标，再操作、回读，并检查其他开关状态。只在首屏找到五项时不能假定第六项不存在，也不能扩大为整页全关。

112 项设备无关回归通过，覆盖独立通知页、混合付款渠道保留、稀疏首屏、前台离开后停止、权限只拒绝、跨页目标与保留项、目标缺失和失败退出码。单元测试不能替代各机型实测。

源码提交 d4ee2d2 的 Windows CI 同样通过 112 项回归，并通过 PyInstaller 打包、命令行及原生 GUI / 图片 / JS API 冒烟测试、便携包和安装程序生成。本次为手动构建验证，未发布新 Release，也未覆盖 0.2.3 安装包。

原始备份、应用列表、通知数据和完整执行日志仅保存在本机 backups/，不上传 GitHub。公开文档只保留机型、版本、操作范围和验证结论。

经机主同意关闭的组件

机主明确选择关闭全部四项后，执行 pm suspend 并回读挂起状态；快应用与仍在运行的广告服务、乐划进程随后停止，第一次检查时四者均未运行。

后台停止仅部分有效：重新运行商店等应用后，广告服务、乐划、快应用平台三个进程再次出现，四个包的挂起状态仍为真。收尾再次停止后，乐划和两个快应用进程均未运行，但 com.opos.ads 已再次运行。具体拉起机制尚未定位，因此只确认「四包已挂起」，不能写成「四项永久关闭」或「广告服务彻底停止」。

组件包名影响
OPPO 广告服务com.opos.ads挂起广告服务组件，不等于验证所有系统广告消失
乐划锁屏com.heytap.pictorial停用锁屏杂志功能
快应用平台com.nearme.instant.platform停用免安装快应用
快应用本地服务com.oppo.instant.local.service停用对应快应用服务

应用商店、下拉搜索和负一屏均确认未被挂起。挂起不会卸载应用，也不清除数据；未来是否被系统重新拉起仍需实际观察。

还原

通知可使用本次筛选清单恢复：

python tool/run.py -s <序列号> chan-on backups/PJA110-<时间>/channels-approved.tsv

三个个性化推荐开关和六个商店推广位可沿上述原路径重新开启。组件恢复：

python tool/run.py -s <序列号> unsuspend com.opos.ads com.heytap.pictorial
python tool/run.py -s <序列号> quickapp on

已执行 run.py finish，插电常亮最终回读为备份原值 0。本机拒绝写入该设置，没有调整安全权限来绕过限制，也不能声称测试期间始终保持了常亮。不再排查时，关闭手机开发者选项总开关，已完成的去广告设置不会因此撤销。
