09 社区问题处理记录

只记 GitHub 上看不到的：同一类表象怎么判定、缺哪台机器的真机验证。逐条回复、标签变化、讨论过程都在 issue 里，这里不重复。

新增一批处理时加三行以内 —— 处理了什么类别、判据是什么、状态落在哪。细节留在 issue 与 PR 里；哪一版修了什么看 CHANGELOG。

判据速查

看到这类现象，先按这条判：

表象判据代码 / 文档
卡在「正在连接手机读屏服务」，或某一步几秒内失败、退出码 1先看日志有没有 UiAutomation not connected、AccessibilityServiceAlreadyRegisteredError。有就是读屏服务被别的工具占着（GKD、自动记账、另一个客户端、旧版 adb），不是机型不适配：要求退出其他工具只留一个客户端，仍失败重启手机。这类报告常以「XX 没适配」的标题出现，不要当机型请求处理（样本见 #323）tool/fast.py:79-95；排查说明
营销通知批量「未确认」ColorOS / 荣耀的系统管家渠道页由独立包承载；先确认页身份，再按回读判成功归档记录
扫描出来的营销渠道明显太少，名字里带「消息」的整类不见看渠道 ID 是不是厂商营销分类号（vivo VPushChannel_0/4/6）。是就该在清单里：分类号能越过跳过词，但营销关键词仍要命中；VPushChannel_1/2 是服务通知，仍应跳过tool/channel_policy.py 的 VIVO_MARKETING 与 classify()
繁体中文界面上 chan-off 全部跳过，日志里「允许通知开关 0 个」不是机型不适配：页面与标题都读到了，缺的是繁体标签。引擎已收「允許通知」「顯示通知」「類別」与繁体营销 / 服务词条（#498）；仍跳过就看界面上实际写法是否不在词表里，按报告者 dump 补词，不要放宽成「页面上的第一个开关」tool/chan_fast.py 的 ALLOW / CHANNEL_GROUP、tool/channel_policy.py 的 KW / SKIP / SERVICE_TERMS
能读到开关但点不动、写不进设置小米系「USB 调试（安全设置）」没开；input keyevent 0 返回 INJECT_EVENTS 即判定被拒小米清单
执行中途 device not found手机断了。等它回来重试一次，仍断开就停止并提示；不把空结果算成功tool/adb_link.py
新机型「没适配」先看诊断里「机型脚本」一行是不是借了同品牌参考脚本。借脚本走安全模式，入口改名就跳过，命中率低属正常，不等于适配失败docs/04
渠道 ID 明显是广告网络（TencentAdNetCH1、ADroiUnion 一类）却没进候选广告网络名编在 ID 里时命中即营销，不再要求渠道名带营销词；ID 是厂商固定车道，比渠道名可靠tool/channel_policy.py 的 AD_NETWORK 与 classify()
清单里缺一个「推荐服务」「常驻通知」一类渠道，扫描报「另有 N 个前台服务渠道未列入清单」（引擎 stderr、命令行、客户端扫描卡片与「复制完整诊断」里都有）看 dumpsys notification --noredact 的 PackagePreferences: 段里该渠道行有没有 mFgServiceShown=true（Android 14 起改名为 mUserVisibleTaskShown；两个名字都在渠道行上，不在 NotificationRecord 记录段）。有就是前台服务的常驻通知，按票面排除；字段是粘性的，渠道发过一次前台服务通知后永久为 true，之后转纯营销也仍会被排除——报告者要它进清单只能手写清单行。找不到字段而清单照样缺渠道，另按机型适配查tool/chan_fast.py 的 FG_SERVICE_MARKS / parse() / scan 分支、ADR-0006
启动 App 后整段在开屏 / 推广页里翻找入口，84 秒后报「没找到 X」不是入口改名，是没校验落点。Phone.start(expect=…) 的判据由机型脚本给（如商店底栏「我的」）：落在别处退一次（返回退出 App 时重新拉起），仍不对就跳过本段并打印前台与期望，不在推广页里继续找tool/fast.py 的 start() / expect_page()
原生鸿蒙只有 HDC，不在支持范围—
某个开关点了没反应、最后报「关不掉」先看该行开关控件是不是 enabled="false"：多是被上级开关禁用（浏览器「摇一摇广告」在上级广告开关关掉后就变灰），点了也不会变。off() 现在不点、单独说明；渠道页里同一判定叫「系统锁定」。报告者说「关不掉」时先要页面 dump 的 enabled，不要直接按机型不适配处理。另一种「关不掉」是点完后整页读空或页面跳走：这一页已无法核对，不能算成功（#486）tool/row.py 的 disabled_at()（#333）、tool/fast.py 的 off() 回读分支（#486）
Windows 弹窗说「缺少 WebView2」，但装的是便携版不一定真缺运行时。先看注册表 HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-…} 的 pv 在不在：在就说明运行时没问题，是解压出来的 Python.Runtime.dll / ClrLoader.dll 带 Zone.Identifier（MOTW）被 .NET 拒载，import clr 失败。对 zip 解除锁定后重新解压，或对解压目录跑 Unblock-File；安装版由安装程序写文件，不受影响gui/winpreflight.py（#228）
Windows 弹窗说「本地程序集被判成远程来源」（load=unresolved）既不是缺运行时也不是 MOTW：这台机器的 .NET Framework 连没有 Zone.Identifier 的本地托管 dll 也按「网络位置」拒载（NotSupportedException，HResult 0x80131515），import clr 失败。新版包在每个 exe 旁自带 <exe>.config 开 loadFromRemoteSources；报告者包里没有这份文件，就是旧版或解压时丢了，换最新版 zip 重新解压。有文件仍报就让他贴 --smoke-gui 的 startup: 行gui/winpreflight.py 的 load_rejected()、gui/dotnet_config.py（#597）
