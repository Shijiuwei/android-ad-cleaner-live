架构总览

这份文件只回答三件事：东西在哪、边界在哪、谁跨过边界说话。 机制与取舍不在这里，每处结论都指向 docs/adr/ 里的一份决定。

一、宿主与进程

谁在哪跑引擎怎么跑
桌面宿主 · 客户端进程gui/launch.py → gui/app.py 的 Api不跑引擎：排步骤、起子进程、收日志、上报错误、只读的 adb 查询；不点按、不改开关
桌面宿主 · 引擎子进程tool/run.py，客户端为每一步起一个读屏、点按、跑机型脚本 / 渠道 / 快应用 / 挂起；不知道这一步之外的事，不写界面、不上报
手机宿主 · 单进程android/ 的 APK，aac_android/inproc.py在本进程的线程里跑同一份 tool/；不是子进程，脚本把进程弄崩会带走整个 App

两个执行宿主（桌面 / 手机）跑同一份引擎与机型脚本。替换只有三处：命令怎么执行、每一步怎么起、屏幕怎么读，都在 Python 层（ADR-0019）。另有一处措辞分叉：手机版没有电脑和数据线，引擎的排查提示按宿主取词（tool/host.py 的 ON_PHONE / CLICKER / CLICK / TAPPED），客户端的诊断行同理（gui/app.py 的 TAP_REFUSED）；判定、控制流与机型脚本不分叉（ADR-0019 增补段）。

二、四条跨边界契约

契约边界谁消费决定
命令与退出码客户端 → 引擎gui/app.py 的 Task / Job一条命令一个 cmd_*(serial, rest) -> int，sys.exit 只在入口一处，转发型命令透出子进程码（ADR-0005）
引擎输出的三态引擎 → 客户端gui/app.py 的 _log()；手机版 aac_android/view.py人话行进界面；#aac:event 只改状态、不进日志；#aac:payload 只进上报（ADR-0004、ADR-0009）
窗口桥前端 → 客户端gui/web/；手机版改由 Compose 直接调 Python（ADR-0018）Api 上的方法名与参数是前端唯一契约，内部的下载 / 上报 / 调度怎么分家都可以变（ADR-0011）
读屏 adapter引擎 → 手机tool/fast.py 的 PhonePhone.reader 是引擎看手机的唯一接口；桌面是 uiautomator2，手机是 aac_android/u2.py（ADR-0001、ADR-0002、ADR-0019）

三、tool/ 模块清单

一次执行会跑到的：

模块拥有什么
run.py总入口：命令分派、退出码、设备信息、备份的存取
fast.py引擎核心：Phone（采样 / 导航 / 拨动）、plan_switches()
recipe_kit.py机型脚本的前导：段包装、入口断言、跳过出口、两个台账（ADR-0029）
chan_fast.py营销通知渠道：ChannelPage（到页 + 认行）、批处理循环
channel_policy.py渠道判定：营销候选、扫描排除、默认不勾、受保护、前台服务
row.py「开关所属的那一行」的唯一定义
wait.py「等到页面认得出」与「等机主解锁」的唯一实现
events.py事件行与载荷行的格式与判定
reader.py读屏 adapter 的接口（Reader）
adb_link.py连接中断的判定与「等手机回来」
backups.py备份目录的命名、扫描与兜底
entries.py入口速查：品牌家族 × 分组 × 三档路径；FAMILY 也在这里
ui_hidden.py「本机 UI 未暴露」渠道名单
ui_session.py读屏会话的本机互斥
troubleshooting.py读屏失败的排查提示
host.py这次执行跑在哪个宿主（手机版 / 桌面），以及随之切换的称呼

只有人手动敲命令才会跑的：

模块拥有什么
adapt.py新机型适配辅助：试入口 → 探路 → 勾选 → 草稿 → 自检
explore.py探路：只读，列出像广告的开关
huawei_channels.py华为 ALN-AL00 的清单式渠道处理，需人工审核清单，客户端不自动跑
gen_brand_taps.py从 docs/手机版教程/brand-taps.json 渲染连点表
gen_site_css.py把仓库根 site.css 渲染进官网两页的共享样式块

客户端侧：gui/app.py 是主体（ClientData / AdbDownloader / Reporter / Dispatcher / Api），gui/launch.py 是入口与打包冒烟，gui/web/ 是桌面版的界面，gui/winpreflight.py 归因 Windows 启动失败，gui/dotnet_config.py 在打包时写随包的 <exe>.config。

四、一次执行的路径

备份 → 任务步骤（广告开关 / 营销通知 / 快应用 / 挂起）→ 收尾 → 结果
  • 步骤清单由 plan_tasks() 按用户的选择拼出，每一步是一个 Task（标题 + kind + 脚本 + 参数）。没勾的项也在清单里，只是带 skip_reason、不碰手机，照样在结果里占一行（ADR-0023）。
  • 没做成的步可以在结果页再跑一轮：retry_plan() 按各步的 kind 与失败段名重建一份计划，新 Job 接住上一轮的结果、按 kind 就地覆盖（ADR-0026）。
  • 状态全部收在 Job 里：单写者 + 锁内快照，界面轮询只拿快照（ADR-0010）。
  • 引擎发回来的东西分三路：人话进日志、事件改状态、载荷进上报（见「四条契约」）。
  • 广告开关那一步里，「这一页该拨哪些」是纯函数 plan_switches() 算的，点击与回读在 off() 里（ADR-0008）。
  • 营销通知那一步里，「到页 + 认行」归 ChannelPage，判定归 channel_policy.classify()（ADR-0007、ADR-0006）。

五、状态

  • 桌面宿主与引擎：稳定。 模块边界由 ADR-0001–0020 钉住；主流程不做整体重构，Phone 保持今天的宽度（ADR-0020）。
  • 手机宿主：provisional。 ADR-0014 / 0018 / 0019 落地晚于其余决定，Kotlin 侧未在本机编译，配对、自动重开无线调试、后台屏等仍待真机验收——读这一层时不要当成定稿。
