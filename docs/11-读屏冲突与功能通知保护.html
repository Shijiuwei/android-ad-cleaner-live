11 读屏冲突排查与“找机位”通知保护

更新：2026-10-26。以下代码改动尚未进入已发布的 0.2.3 安装包；0.2.3 用户可以先按排查和还原步骤处理。

本次反馈说明了什么

原反馈环境为 Windows 11、小米 18 Pro Max / OS4.0.27，错误包含 AccessibilityServiceAlreadyRegisteredError。用户升级到 0.2.3 后仍失败，随后同时关闭 GKD 和自动记账，反馈可以开始处理。

这提供了可用的冲突排查方向，但尚未逐个工具、逐个模式对照，也未独立复现。因此不能断言是哪一个工具占用服务，更不能推断所有无障碍服务都必须关闭。0.2.3 的会话清理和互斥仍然保留；本次改进的是排查能力与提示。

Android 的 UiAutomation 注册代码限制同一时刻注册一个 UiAutomation 服务，这不等于普通无障碍服务只能开启一个。GKD 官方说明和自动记账项目说明也表明相关工具可能使用无障碍或 Shizuku；这些技术背景不能证明反馈手机上的具体占用者。

读屏失败时的处理顺序

  1. 保持手机解锁，退出重复的去广告客户端，以及正在操作这台手机的 Appium、UI 检查器等任务。
  2. 检查 GKD、自动记账等工具是否开启自动化、读屏或 Shizuku 模式。只暂停你确认可以暂停的功能；如有必要，由本人暂时关闭对应 App 的无障碍服务。
  3. 保留自己依赖的屏幕阅读器与辅助服务，不要一键关闭全部无障碍。暂停后点「检查读屏连接」，每次改变一项后复测，便于定位。
  4. 仍失败时，可由机主手动重启手机；解锁后先不启动上述自动化工具，再检查。继续失败则复制完整诊断。
  5. 去广告结束、读屏会话退出后，按需恢复之前暂停的工具。

客户端不会代替用户关闭无障碍总开关、修改服务名单、强停其他工具或重启手机。失败后的辅助检查只通过 adb 读取总开关和已配置服务数量，最多等待 3 秒；服务标识和应用名单不写进诊断。读取失败不会覆盖原始异常。

总开关开启或服务数量大于零只是线索，不代表已经找到占用者；读到关闭或零项，也不能排除独立的自动化 / Shizuku 会话。界面的读屏检查结果及执行完成页都会给出排查提示，避免提示被长堆栈淹没。

“找机位”通知的保护范围

用户另报小米 18 Pro 系列的“找机位通知”被营销通知流程误关。该功能属于用户需要的功能通知，不能因为渠道名或 ID 带“推荐 / 活动 / recommend”等词就关闭。

当前保护名称含“找机位”“机位推荐”“推荐机位”的渠道，兼顾简繁体、空格和零宽字符。保护覆盖：

  • 扫描候选：排除这些功能通知。
  • 客户端列表：即便收到旧扫描结果，也不把它放入可全选的营销列表。
  • 旧清单执行：核对手机当前渠道名、渠道 ID 和清单描述，命中保护规则就跳过；只有这些项目时不启动读屏。
  • 实际点击前：再次读取当前名称，避免旧清单标签或扫描后改名绕过保护。
  • 复查统计：受保护渠道不计入“营销渠道仍开着”，并注明保留；普通营销渠道仍正常处理。

目前尚未收到这项功能的真实包名、完整渠道名称和渠道 ID；当前是名称保护，不是已在反馈手机上验证的精确 ID 适配。如果其实际名称与上述词不同，仍需要补充信息后完善规则。

已误关的渠道怎样恢复

可以进入该功能所属 App 的系统通知设置，找到“找机位 / 机位推荐”对应渠道，只重新开启这一项。

有原始清单时，也可将该渠道对应的一行复制到单独的 restore-photo-spot.tsv，保留原包名和渠道 ID，然后执行：

python tool/run.py -s "<序列号>" chan-on "backups/<原备份目录>/restore-photo-spot.tsv"

执行后查看回读结果，确认该渠道为开启。新保护规则只阻止关闭，不阻止明确执行的还原。扫描或再次去广告不会自行开启以前关闭的渠道，以免覆盖用户原本的选择。

验证与待确认项

123 项设备无关回归通过，覆盖只读检查与超时、服务名单不泄露、原始异常保留、GUI 错误提示、功能通知候选排除、旧清单保护、点击前复核、已有关闭状态保留以及定向还原。原生 GUI 冒烟另验证模拟读屏失败时排查卡片和按钮实际出现。

代码提交 92a539f 已通过 Mac 本地回归和原生 GUI 冒烟，以及 Windows Actions #40213007991 的回归、PyInstaller 打包、原生 GUI / CLI 冒烟、便携包和安装程序生成。本次 Windows 构建为手动验证，未上传到 Release，也未替换 0.2.3 已发布安装包；打包通过不能代替反馈者手机上的复测。

本轮没有关闭任何实机无障碍服务，也没有代替反馈者重新开启通知。仍需反馈者提供渠道元数据，并在其设备上验证新的筛选和定向还原；同时关闭两个工具后成功，不能记成单一工具根因已证实。
